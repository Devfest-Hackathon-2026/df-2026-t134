# 学習画面のデザインと検証

## 方針

中高生が短いレッスンを進めやすいように、暖色の背景・明確な文字の階層・余白を共通化する。教材の本文は静止させ、ユニットの装飾と操作への反応に動きを集める。

| 対象 | 表現 |
|---|---|
| 共通 | アイボリー背景 `#FFF8F2`、本文 `#342C29`、補助文字 `#74665D` |
| Unit 1 | 未来の学習ラボ。テラコッタ、軌道を描くモチーフ |
| Unit 2 | AIの創作スタジオ。アンバー、紙と図形のモチーフ |
| Unit 3 | 冒険する学習ワールド。オリーブ、山と太陽のモチーフ |

テーマは `app/lib/design/chapter_theme.dart` に集約。レッスン画面は取得した教材の `unitId` からテーマを選ぶ。未定義のユニットは共通テーマに戻る。ユニット・教材は取得結果を表示し、未配信の教材をUIで作らない。

## 情報の整列と移動

- 学習パスはユニット単位の横ページ。スワイプ、ユニットタブ、前後ボタンを利用できる。
- レッスン一覧から選ぶと詳細が切り替わり、「はじめる」で遷移する。ロック中は条件を示して開始ボタンを無効にする。
- ユニットごとの選択を画面内で保持する。初期表示は次に学ぶレッスンのユニット。
- 840px以上は一覧と詳細を横に並べ、それ未満は縦に並べる。内容は縦スクロールできる。
- ログイン、プロフィール、レッスン、結果にも同じ配色・余白・ボタンを適用する。
- 進捗・XP・アンロック条件は既存のサーバー応答に従う。

## モーションと負荷

- 横移動と問題表示は320ms、詳細の切り替えは220ms、結果の出現は600ms。
- 常時動く装飾は表示中の画面に1つ。小さいCustomPainterをRepaintBoundaryで分離し、画面全体を毎フレーム再構築しない。
- 隣のユニット、非表示ルート、バックグラウンドでは装飾を停止する。
- OSのアニメーション抑制とヘッダーの「動きを控える」を尊重する。アプリ内の選択はセッション中のみ保持する。
- 大きな動画、ぼかし、パーティクル、外部アニメーション依存は追加しない。

## 検証

Docker内で通常の `make check-app` 相当の整形・静的解析・全Widgetテストを実行する。

- `chapter_ui_test.dart`: 幅360/768/1366px × 文字100/200%、ユニット移動、選択保持、ロック、プロフィールの操作、色のコントラスト、装飾の停止と再開。
- `lesson_responsive_test.dart`: 同3幅・文字200%で実教材6問を回答し、結果から学習パスへ戻る。穴埋めの回答は狭い画面でも折り返す。
- 既存の認証・進捗・採点・リトライのテストも継続する。

描画確認は任意の `preview_capture_test.dart` で行う。通常実行ではスキップする。製品に同梱したフォントを読み込むため、外部フォントの準備は不要。先に `mkdir -p .company/ui-qa` を実行する。

```sh
docker compose --env-file /dev/null -p ailearn-ui run --rm --no-deps -T \
  -v "$PWD/.company/ui-qa:/capture" app \
  flutter test --dart-define=CAPTURE_UI=true test/design/preview_capture_test.dart
```

画像は `.company/ui-qa/` に出力される。Widget描画とブラウザの描画は異なるため、実ブラウザでのタッチ・キーボード・スクリーンリーダーの確認、および低スペック実機でのフレーム時間測定は別途必要。今回の環境ではブラウザ接続を利用できず、実機の60fpsは未検証。

## 新演習との統合（2026-11-10）

プロンプト作成・AI評価とハルシネーション探しは既存のユニットテーマを継承する。送信・再試行・スキップ・評価パネルは共通のスクロール領域に収め、利用可能な高さの55%を上限にする。ソフトキーボードで画面が縮んでも問題・入力側に領域を残す。送信時は入力フォーカスを外し、キーボード表示中は常時装飾を停止する。

`prompt_responsive_test.dart` では文字200%・360px幅・キーボード相当の420pxインセットで、入力の保持、AI停止時の表示、スキップまで確認する。`live_check` は契約定義のみのため、未実装の演習UIや導線は追加しない。

## 紙しばい（story）

短いアニメーションの紙しばいとして、落ち着いて読めることを優先する。

- 流れ: 場面を 1 枚ずつ（絵・話す人・セリフ）→「ユイはどうする？」と選択肢 →「これにする」→ えらんだ選択肢の「そのあと」の場面 → いつものフィードバック（正解！／おしい！、「いちばんよい選択」、解説）。まちがえた問題は、ほかの演習と同じく最後に 1 回だけもう一度出る。
- 場面のカード: 3:2 の絵（角丸 20、画面の高さの 38% まで）、話す人のラベル（アイコン＋名前。色だけで区別しない）、セリフ（18px・行間 1.7、ナレーションは補助色）。絵のない場面は前の場面の絵を見せ続ける。絵がまだない・読み込めない・ローカルの Emulator のときは、ユニットの色の淡いグラデーションと本のアイコンの代わりの絵にする（壊れた画像を出さない）。
- 進め方: 下のバーの「つぎへ」か、カードのタップで次の場面へ。場面の間は「お話をとばして、えらぶ」でとばせる（ふくしゅうのとき用）。上に「場面 2 / 4」「そのあと 1 / 3」を出す。
- 切り替え: 320ms のフェードと 4% の横スライド。OS のアニメーション抑制と「動きを控える」では切り替えを即時にする。絵の代わりの表示は静止し、常に動く装飾はヘッダーのモチーフだけ。
- 音声: 場面ごとの小さな「よみあげる」ボタンだけで、自動再生はしない（教室では音を出せないことがある）。字幕は常に表示する。音声がない・再生できないときもセリフはそのまま読める。場面を離れると止まる。
- 絵と音声は Cloud Storage（`images/scenes/`・`audio/lines/`）から読む。ログインしたユーザーだけが読める。

`story_responsive_test.dart` では幅 360/768/1366px × 文字 200% で、全場面 → 選択 →「そのあと」→ フィードバックまで進め、操作パネルが高さの 55% 以内に収まることを確認する。`story_widgets_test.dart` では絵あり・なし、音声あり・なし・再生失敗、動きの抑制を確認する。

## ワークブックの構成（2026-11-10）

- 書体は全画面で **WDXL Lubrifont JP N**。Google Fontsの `ofl/wdxllubrifontjpn` から取得したRegular 400を `app/assets/fonts/wdxl/` に同梱する。SIL OFL 1.1を同じディレクトリに保持し、Flutterのライセンス表示にも登録する。約9.9MiBのフォントをローカル配信するため、実行時のGoogle Fontsリクエストは発生しない。
- XP・連続学習・接続状態・設定はアプリコット `#F2BE82` の最上部バーにまとめる。狭い幅や文字拡大では折り返す。
- 直下に左揃えのユニットタブを配置し、挨拶は教材側へ移動。通常文字サイズでは360/768/1366pxのいずれも本文ページを画面上端200px以内から開始する。
- 大きな丸角のヒーローパネルをやめ、教材の実際の章番号とタイトルを組み合わせる。レッスン一覧と詳細は異なる形状を使い、画面全体が均一なカードの反復にならないようにする。
- 動きの抑制・横スワイプ・選択保持・ロック条件は引き続き維持する。

## ライブ検証（live_check、Q10）

本物の AI の答えを探偵のように調べる演習。Unit 3 のテーマ（オリーブ・山と太陽）を継承し、1 つの問題の中で 3 つの段階を切り替える。

| 段階 | 表示 | 操作（下の操作パネル） |
|---|---|---|
| 質問を書く | テーマと 3 ステップの説明、質問の例（チップ）、入力欄と文字数（API と同じくコードポイントで数える）、個人情報の注意、ブロック時の説明 | 「AI に質問する」。個人情報らしい文字があれば送る前に確認ダイアログ |
| AI が答えるまで | 生徒の質問と、虫めがねが 3 本の線の上をゆっくり往復する絵（2.4 秒周期、RepaintBoundary で分離）。動きを控える設定では静止 | 送信ボタンがスピナーになる |
| 調べる | 生徒の質問、事件ファイル（まちがいの数・えらんだ数・「調べる」の残り回数）、文ごとのカード。カードをタップでまちがい候補に印、各カードの「🔍 調べる」でその文の出典（サイト名、新しいタブで開く）をカードの下に表示 | 「これで決定」 |

- 正解（書きかえ前の文）は回答するまで画面に出さない。出典は文との見くらべ方だけを添えて表示し、正誤は言わない。書きかえた文の出典は元の文の出典なので、見くらべると誤りが分かる。
- 回答後は Q2 と同じ判定表示（見つけた・見のがし・正しい文だった、色と文字とアイコン）と、元の文・見ぬくコツ、答えのもとになった出典の一覧を出す。まちがえた場合は Q2 と同じく最後にもう一度出る（新しい質問から）。
- 出典はモーダルではなくカードの下に表示する。文と出典を並べて見くらべられるほか、文字 200%・狭い画面でモーダルを開くと Flutter のセマンティクス計算が失敗する事象をテストで確認したため。
- AI が止まっている（503）・1 日の上限（429）は理由を説明し、スキップできる。上限のときは再送ボタンを出さない。通信エラーは入力・印を残したまま再送できる。「調べる」の失敗はその文の下に表示する。
- 外部ページは `url_launcher` で新しいタブに開く。`http` / `https` 以外のアドレスは開かない。

`live_check_responsive_test.dart` で 360 / 768 / 1366px × 文字 200% の通しプレイ、キーボード相当の 420px インセットでの入力保持と AI 停止時のスキップ、狭い画面での出典表示を確認する。

## 回答を確かめる演習

固定ハルシネーション問題・ライブチェックとも、質問とAI回答を読んで正しさを判断する。回答はまとまった段落として表示し、番号付きの文カードに分割しない。実際の誤り件数は採点前に表示しない。

- PCはドラッグ、スマホは長押しで回答中の範囲を選び、「この部分が間違い」でハイライトを付ける。複数箇所を指定でき、それぞれ取り消せる。
- ライブチェックは選んだ部分から出典を調べる。複数の内容にまたがる範囲なら、どの内容を調べるかを選ぶ。
- 「誤りはない」は明示的な回答。初期状態や指定をすべて取り消した状態では回答を送れない。指摘と「誤りはない」は同時に選べない。
- 正誤判定は従来の文IDを使う。UIの文字範囲がまたがる各文を指摘として採点し、正しい文まで指定した場合は誤検出として扱う。単語の完全一致を要求する採点ではない。
- 正しい回答への「誤りはない」、誤りの見逃し、正しい内容の誤検出を区別して解説する。ライブの正解側にも出典を表示する。
- ライブ回答は0〜設定上限の誤りをサーバー側で選ぶ。0件の場合は誤り注入のモデルを呼ばない。公開レスポンスのerrorCountは互換用の上限で、実際の件数を示さない。

本番更新時は新しいWeb UI、API、問題文をまとめて反映する。教材はHosting/APIの再デプロイだけでは更新されないため、教材差分の確認・本番反映が別途必要。既存の学習記録・XPは保持する。今回の実装作業では本番配備・本番教材の変更・有料AIの生成は行わない。
